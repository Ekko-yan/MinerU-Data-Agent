## 2. 赛题理解

- Data Agent 不只是模型推理，而是规划、工具调用、多步执行和结果验证。
- 语料加工的核心痛点：文档类型多、版面复杂、日志不可追溯、失败难恢复。
- 本方案目标：把 MinerU 解析能力工程化为可评测、可复现的数据智能体。

## 3. 系统架构

- 前端：中文 Web 控制台。
- 后端：FastAPI 异步任务服务。
- Agent：规划、执行、结构化、质检。
- 工具：MinerU CLI / 本地 mineru-api。
- 存储：任务目录、日志、manifest、JSONL。

## 4. 核心工作流

1. 上传文档。
2. 自动生成任务记录。
3. LLM 或规则生成执行计划。
4. 调用 MinerU 解析。
5. 聚合原始产物。
6. 生成统一结构化 JSONL。
7. 输出质量检查与可追溯日志。

## 6. 结构化输出格式

- `structured_manifest.json`：文档级索引和统计。
- `structured_chunks.jsonl`：元素级片段。
- `agent_result.json`：计划、质检、结果路径和预览。
- 展示一个 JSONL 片段示例。

## 7. 复杂任务与稳定性

- 并发限制：避免多任务抢占资源。
- 超时控制：公式密集 PDF 不会无限运行。
- 删除任务：清理持续运行的进程。
- 日志追踪：实时查看 MinerU CLI 进度。
- 编码兼容：减少 Windows 命令行乱码影响。
